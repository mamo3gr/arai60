## step 1

`m x n` のグリッドが与えられて、左上のスタートから右下のゴールまでの総経路数を数える問題。通れないセルなど、移動に制約はない。

高校数学でやった気がする。ゴールに辿り着くには `(m-1)` 回だけ下に、`(n-1)` 回だけ右に動く必要がある。これらの移動を `down`, `down`, ... `right` と並べたときに、この順列の総数を数えれば良い。  
同じものを含む並べ替えは、同じものを含む階乗で割れば良いので、`{(m-1) + (n-1)}! / (m-1)! / (n-1)!` .

出題意図としてはDPで解け、ということなんだろうな。小さいm, nでの結果をもとに、大きなm, nに対して答えを出すことを考える。  
`m = 1, n = 1` とすると、1通り。  
次に `m` をインクリメントしてみると、まだ1通り。`m = 2, n = 1`.  
ここからは、`f(m, n)` のように表すことにする。  
`n` をインクリメントすると、2通りになる。`f(2, 2) = 2`.  
さらに `m` をインクリメントすると (`m = 3, n = 2`) 、次のように考えられる。

* すぐに `down` すると、残りのルートは `f(2, 2)` の場合と一緒
* 右に行くと、`f(3, 1)`.

したがって、`f(3, 2) = f(2, 2) + f(3, 1)` かな。  
つまり、`f(m, n) = f(m-1, n) + f(m, n-1)`.  
mかnのどちらかが1になるまで、デクリメントしながら再帰すれば良さそう。

計算量を見積もる。  
`m` をデクリメントするごとに2回の再帰、同様に `n` をデクリメントするごとに2回の再帰が必要なので、`O(2^(m+n))` になる。
`m` や `n` は最大100で、2^(100+100) を考えるとどう考えても終わらない。  
途中で同じ `f(m, n)` を計算していると思うのでメモ化が使えそう。  
一番カンタンな方法としては、ヘルパー関数を用意して、`functools.lru_cache` デコレータを付ける。  
https://docs.python.org/3.13/library/functools.html#functools.lru_cache  
このキャッシュに必要なメモリは、`O(m x n)` になる。また、再帰でスタックを最も積んだとき、`O(m + n)` の空間が必要になる。  
メモ化によって、`f(m, n)` はそれぞれ一度だけ計算されるので、処理時間としては `O(m x n)` で見積もれそう。Pythonの処理能力を10^7 steps/sec とすると、100 * 100 / 10^7 = 1ミリ秒くらいのオーダーを予測する。

この時点で見えている幅を書いておく。

* 再帰をスタックに書き直すことはできそう。ただし現時点で再帰のほうが書きやすそうに見える
* キャッシュは `lru_cache` の他に、二次元配列やdictでも持てる
  * 前述のリファレンスを読んだ感じ、引数=key, 結果=valueのdictを使っているようなのであんまり差はなさそう
  * 二次元配列の方がアクセスは速そう（ハッシュ計算がない分）
* `f(m, n) = f(n, m)` で、これは何かに使えるのではないか

## step 2

二次元配列でのメモ化を考える。`f(m, n)` を `m x n` の二次元配列に格納する。  
左上が `(0, 0)` とすると、最も上の行と、最も左端の列は1になる。  
この初期化から、右下に向かって値を埋めていけば良い。
`f(m, n) = f(m-1, n) + f(m, n-1)` だから、あるマスを埋めたければ、その上と左の値を足せば良い。  
つまり、行ごと、あるいは列ごとに走査して埋めていけるということだ。

配列の初期化では、念の為すべて `None` で埋めてみた。これだと、ミスして未処理の要素にアクセスしたときに `NoneType` と int の足し算になって例外が上がる。

マスを埋める式を眺めると、いま埋めたい行は、直前に処理した行があれば処理できる。
それ以前の行は不要なので、2行ぶんの配列だけ持っておいて、行ごとの処理が終わるたびにスワップすれば良い。  
もうちょっと考えると、実は1行だけで済むことが分かる。処理が終わった左と、上＝マス自分自身をを足して、同じアドレスに書き込めば良い。
