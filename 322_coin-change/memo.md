## step 1

何枚かのコインを表す配列 `coins` が与えられ、それらを足し合わせて `amount` が作れるとき、最小のコインの枚数を求める。`coins` の各要素は使えるコインの額であり、それぞれのコインは何枚使っても良い。制約は次の通り。

* `1 <= coins.length <= 12`
* `1 <= coins[i] <= 2^31 - 1`
* `0 <= amount <= 10^4`

0から `amount` までを、`coins[i]` で作れるかDPで調べていくのが良さそう。  
目標値をインクリメントしていくか、作れることが分かっている額から各 `coins[i]` で配っていくか。
後者のほうが手作業に近いが、前者のほうがプログラムとしては素朴でバグを埋め込む可能性が低そう。
まずは前者をやる。他のパターンはstep 2で書いてみる。

処理時間を見積もる。
`A = amount`, `L = coins.length` とすると、時間計算量は `O(AL)`.
というのも、`for i in range(amount+1)` と `for coin in coins` の二重ループになるから。
Pythonの処理能力を10^7 steps/sec とすると、
10^4 x 12 / 10^7 = 12ミリ秒くらいのオーダーを予想する。

使うメモリは、それぞれ `i` をコインで作るための最小枚数を保存するための `O(A)`.
28 bytes/int とすると28 x 10^4 = 280 KBくらいのオーダーを予想する。

### BFSとかDFSとか

勉強のためにBFS, DFSも書いてみる。

BFSは、1枚で作れる場合、2枚で作れる場合、…を順番にキューに入れていく。
キューには枚数と合計額を入れる。合計額が `amount` と一致したら終了。
少ない枚数からキューに入れているので、`amount` と一致したらすぐに終了できる（これが偉い）。
枝が広がっていくので、訪問済みの合計額は探索をスキップしないと計算量が爆発する
（例えば、for each 1枚ケースに対して、for each coinで増える）。  
Optionalとして、`coins` を昇順ソートしておけば、`current + coin` が `amount` を超えた時点で以降のコインを試す必要がなくなる（枝刈り）。
さらにOptionalとして、双方向に探索するというのもある。

DFSでは、同じコインを連打して `amount` を目指す。TLEしないように工夫がたっぷり必要になる印象。
まず、コインを降順に並べておくと収束が速い。
現状のベスト枚数を覚えておいて、それよりも多い枚数の枝は探索しない。
また、残りの `amount` を `coin` で割った数が、理論下界で（同じ`coin`でぴったり払えたときの数だから）、現状のベストよりも多いならスキップする。
