## step 1

`n` 枚の壁と `k` 色が与えられたとき、これら壁を塗り分けるパターン数を求める。
ただし、2枚よりも多くの（つまり3枚以上の）壁を連続して同じ色では塗れない。制約は次の通り。

* 1 <= n <= 300
* 1 <= k <= 10^5

例で考えてみる。n=4, k=3のとき。
最初 (n=1) はk=3色のどちらかを選ぶ。つまり `f(n=1,k=3) = 3` である。
次は、同じ色を続けるか、他の色を選ぶ。つまり `f(n=2,k=3) = 3 * 3` である。
nがインクリメントされるとき、`f(n-1, k)` に `k` を単純にかければ、
すべての組み合わせ数が求められる。
が、ある色について、すでに2枚連続していて、もう一度は続けられない、というパターンを含んでいる。
ということは、「ある色が2枚連続している枚数」を `n-1` の答えから受け取れればいいのかしら。
これを `g(n,k)` とする。

`f(3,3) = f(2,3) * 3 - g(2,3) = 24`.
木構造に見立てると、分岐する元のノード数 `f(2,3) = 9` のうち、3連続になるものは `g(2,3) = 3` 通り。
残り6通りでは、それぞれ2連続になる子ノードがひとつだけ生える。これが `g(3,3)` になりそう。

あとはDP (tablation) の容量で、`n=1` のときから目的の `n` まで計算すれば良い。

処理時間とメモリ使用量を見積もる。
時間計算量は `O(N)`. Pythonの処理能力を10^7 steps/sec とすると、
300 / 10^7 = 30マイクロ秒くらいのオーダーを予想する。
空間計算量も `O(N)`. `f(n,k)` と `g(n,k)` を保存しておく領域が必要。
（と書いて気がついたが、`n` と `n-1` の場合だけ覚えておけばいいので、`O(1)` でもいける）。
