## step 1

ユニークな整数から構成される配列 `nums` が与えられたとき、すべての並び替え (permutations) を返す。
順序は問わない。制約は次の通り。

* 1 <= `nums.length` <= 6
* -10 <= `nums[i]` <= 10

シンプルに考えると、並び替え後のlistに対して、`nums` から一つ選んで追加を繰り返していく。
これをコードに落とし込むにはどうしようか。

引き継ぎと作業を考えてみる。例えば `nums = [1, 2, 3]` のとき、
「1番目を列べておいたよ。後は0番目と2番目が残ってるよ」という引き継ぎを受けることを考える。
ここから、残りの数字それぞれに対して、並びに追加 -> 残りを記録 -> 引き継ぎ、とすればよい。
引き継ぎにはスタックが使えそう。

処理時間とメモリ使用量を見積もる。
時間計算量は ~~ `O(N!)` ~~ `O(N x N!)`. ただし `N = nums.length` である。
Pythonの処理能力を 10^7 steps/sec とすると、~~6! / 10^7 = 72マイクロ秒くらいのオーダーを予想する。~~
6 x 6! / 10^7 = 432マイクロ秒くらいのオーダー。
~~空間計算量も ~~ `O(N!)` ~~ `O(N x N!)`. スタックに積まれる単位は、すでに並べた数字のインデックス、
まだ並べていない数字のインデックスで、どの状態でも合計で `N` 個のintが必要。
~~6! x 6 x 28 bytes/int = 121 KBくらいのオーダーを予想する。~~
6 x 6! x 6 x 28 bytes/int = 726 KBくらいのオーダー。

## step 2

GeminiとChatGPTにコードをレビューしてもらいつつ整理する。

* 数字そのものではなくインデックスで管理しているので不必要に煩雑。
* 新しいlistを作ったり、要素を排除したlistを作ったりするのに不必要にコストがかかっている。

時間計算量・空間計算量は `O(N!)` ではなく `O(N x N!)` と書くらしい。
また、前述のlistを作るコストのせいで、`O(N^2 x N!)` になってしまっていた。

より効率的な方法として、バックトラッキングと呼ばれる方法があるらしい。
並び替えの先頭に対し、`nums[0], nums[1], ..., nums[N-1]` と決めた場合をそれぞれ考える。
まず `nums[0]` を先頭にしたとして、次の要素を `nums[1], ..., nums[N-1]` の中から決める。
候補の先頭である `nums[1]` を選んでおいて、さらに次の要素を選ぶ。
…と最後まで行ったら、ひとつ手前の選択肢まで戻り、また最後まで進む。これを繰り返す。
ここまでの処理には再帰が使える。
さらに本問の場合は、`nums` 内の要素をswapすることで、配列の要素のコピーなしに状態を管理できる。
ただし、並び替えが完了したときに `nums` の浅いコピー（参照）をappendしてしまうと、
続く処理でデータの中身が変わってしまう。深いコピーが必要。

これで、時間計算量が `O(N x N!)`, 空間計算量が `O(N)` に減らせる。

#### https://github.com/huyfififi/coding-challenges/pull/44

step1は自分のstep1と同じ解き方。
`remaining` と `generating` という名付けは分かりやすい。

https://github.com/huyfififi/coding-challenges/pull/44/changes#r2693577983

>使用中または未使用の整数のフラグの配列を用意し、未使用の整数を generating に加えていくという方法もあります。

`remaining` は `used: list[bool]` として、
`nums[i]` を使ったかどうか（`generating` に加えたかどうか）を管理する。
また、`generating.pop()` を使うことで、リストのコピーなしに `generating` を一つ手前の状態に戻せる。

手なりで配列のコピーをどんどんやっていたけど、「それだと `O(N)` かかってイヤだなあ」と感じる、
ということが必要だったのかもしれない。解けること・シンプルに書けることに釣られてしまった。

#### https://github.com/garunitule/coding_practice/pull/50

並び替え結果を `permutation` として、ここに `nums` の要素をappendしていく。
`nums` の要素はユニークなので、`not in permutation` で使用済みかどうかは分かる。
バックトラックは `permutation.pop()` でやる。

配列の深いコピーを `permutation[:]` のように書くの、Geminiもやっている。
スライスで書くとコピーになるからそうなんだろうけど、
深いコピーをしたいのなら `copy.deepcopy(permutation)` と書く方が素直に思える。
デメリットとしては `copy` モジュールのインポートが必要になる。

#### https://github.com/h1rosaka/arai60/pull/51

並び替え中 (`current_list`) と、残り (`left_over_list`) を引き継いでいく (step1).
リストがコピーできればいいので（要素はもともとimmutableなので）、`copy.copy` で十分だった。

`permutations.copy()` だと `copy` モジュールが不要そう。
https://docs.python.org/3.13/library/stdtypes.html#sequence.copy

>「探索中に一時的に状態を変更し、再帰から戻るときに必ず元に戻す DFS」をバックトラッキングというらしい。
